# DG-KAN 实验真实性审计 2026-05-04

本文件用于纠正此前把 proxy / dry-run 指标写成“跑完实验”的错误。结论先写清楚：

```text
v6.4 到 v9.1 中多数“结果复盘”不是可作为论文或结论依据的真实训练实验。
它们主要由固定基线表、jitter、metric_row 一类生成函数产出。
这些版本的结论、claim map、route decision 必须全部降级为 proxy 草案，不能当作 empirical result。
```

## 为什么这是严重错误

我把“按计划生成 artifact / CSV / 复盘文档”错误地等同于“真实训练已经完成”。这是我的错误，不是用户授权，也不是计划要求。以后任何结果必须明确标注 provenance：真实训练、profiling、proxy、dry-run、还是设计草案。

## 重跑规则

从现在起，任何重新跑出的结果必须满足：

1. 结果文件记录真实命令、git 状态、数据集路径、seed、epoch 数、batch size、设备、开始/结束时间。
2. 每个 claim 必须能追溯到 raw per-seed row 和 epoch trace。
3. 禁止继续生成 proxy / synthetic / dry-run 指标表。
4. 禁止把 `BASE_ACC`、`ACC_1K_FAST`、`metric_row()` 生成的表格写成真实训练结论。
5. 重新跑 v7-v9 之前，必须先实现对应架构的真实 trainable module；不能靠重跑旧 proxy runner。
6. 已确认的 proxy runner / analyzer 必须运行即阻断，不能提供 opt-in 继续生成假数据。

## 重跑顺序

```text
R0 provenance cleanup:
  quarantine / relabel v6.4-v9.1 proxy artifacts.

R1 empirical baseline restore:
  rerun known-real core on MNIST / Fashion-MNIST / KMNIST with small seed count.

R2 empirical vision restore:
  implement real trainable PatchKAN / LFK modules, then run CIFAR-10.

R3 scale-up:
  only after R2 passes, run CIFAR-100 / TinyImageNet-lite.

R4 ImageNet:
  only after real code and smaller-scale gates exist, run ImageNet-100/200/1K.
```
